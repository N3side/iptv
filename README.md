## Алгоритм «телевизор перестал работать» — подробно

Отталкиваемся от вашей формулировки: **если просто не работает (нет картинки)** — смотрим **маки → влан → V (pktfilter) → igmpsnoop group**. Ниже — по шагам, что именно смотреть и как читать вывод.

---

## Шаг 1. MAC-адреса на порту — `statistics mac 8`

```
statistics mac 8
```

Смотрим, есть ли MAC **приставки** и в каком VLAN.

**Как читать:**
- MAC приставки виден в **IPTV VLAN** (у нас PVID 1201) → приставка достучалась, L2 в порядке. Идём к Шагу 2.
- MAC **нет вообще** → приставка не подключена / кабель приставка–модем / модем не бриджует / приставка выключена. Дальше DSLAM не виноват — к абоненту.
- MAC есть, но **не в том VLAN** (например, в 2846-интернет, а не 1201) → модем пускает приставку не в IPTV-VLAN. Проблема на модеме (VLAN IPTV / bridge).
- MAC модема в 2846 и 1308, а приставки в 1201 нет → модем работает, приставка не доходит до IPTV-PVC.

**Пример (наш порт 8):**
```
1201  ec:4c:4d:e8:41:c0   ← приставка в IPTV VLAN ✅
1308  ec:4c:4d:e5:68:c2   ← модем TR-069
2846  ec:4c:4d:e5:68:c1   ← модем PPPoE
```
→ MAC приставки в 1201 есть → Шаг 2.

---

## Шаг 2. VLAN / PVID — `switch vlan portshow 8`

```
switch vlan portshow 8
```

Смотрим **pvid** порта — должен быть **IPTV VLAN** (super channel).

**Как читать:**
- PVID = IPTV VLAN (у нас 1201) и совпадает с рабочими IPTV-портами → ок, Шаг 3.
- PVID = интернет/управление (2846/1308) → трафик приставки уходит не туда, картинки не будет. **Сменить:**
  ```
  switch vlan pvid 8 <IPTV_VLAN>
  ```
- Сверить с рабочим портом того же DSLAM:
  ```
  switch vlan portshow <рабочий_IPTV_порт>
  ```

**Дополнительно — статус VLAN:**
```
statistics vlan
statistics vlan 1201
```
`F` — работает, `U`/`T`/`E` — не в работе. Если IPTV-VLAN не `F` — проблема выше (агрегация/upstream), не в порту.

---

## Шаг 3. «V» — фильтр пакетов — `switch pktfilter show 8`

```
switch pktfilter show 8
```

Смотрим колонку **igmp** и **dhcp**, и режим **PPPoE-Only**.

**Как читать (легенда: V = pass, `-` = filter out, # = don't care):**
- **igmp = V** — join-запросы проходят. Обязательно для IPTV.
- **dhcp = V** — приставка получит IP.
- **ip/arp/pppoe = V** — норм.
- **PPPoE-Only = D** — режим «только PPPoE» выключен. **Если `E` (включён)** — весь не-PPPoE трафик (в т.ч. IPTV multicast) режется → чёрный экран. Выключить:
  ```
  switch pktfilter set 8 none
  ```
- Если `igmp = -` (заблокирован) → join не проходит. Исправить:
  ```
  switch pktfilter set 8 none
  ```
  (или выставить нужные флаги, если политика требует).

**Пример (наш порт 8):** `pppoe/ip/arp/dhcp/igmp = V`, `PPPoE-Only = D` → фильтр чист ✅, Шаг 4.

---

## Шаг 4. IGMP snooping group — `statistics igmpsnoop port group 8`

```
statistics igmpsnoop port group 8
```

Смотрим, есть ли **подписка** на multicast-группы.

**Как читать:**
- **Список групп есть** (например `vid 1200, 239.255.11.74, source 10.35.66.101`) → приставка прислала join, snooping видит, порт зафиксирован. Значит **со стороны DSLAM подписка работает** — идём к трафику (Шаг 5) и к абоненту.
- **Пусто** → приставка не шлёт join. Причины:
  1. **mvlan не зафиксирован** на порту — проверить:
     ```
     switch igmpsnoop mvlan show *
     ```
     Порт должен быть **F (Fixed)** на multicast-VLAN. Если `U`/`T`/`-` — зафиксировать:
     ```
     switch igmpsnoop mvlan set <mvlan_vid> 8:FU MULTICAST
     ```
  2. Приставка не в IPTV-VLAN (Шаг 2) / фильтр режет IGMP (Шаг 3).
  3. Проблема на стороне абонента: модем не бриджует IPTV-PVC, IGMP proxy в модеме выключен, приставка/кабель.

**Сверить mvlan и PVID:** у нас PVID 1201, mvlan 1200 — это нормально (super-channel VLAN порта и multicast-VLAN могут различаться), главное порт **F на mvlan**.

## Шаг 5 (дополнение). Трафик на IPTV-PVC — `statistics port 8 1 32`

```
statistics port 8 1 32
```

Снять **дважды** с паузой 1–2 мин, сравнить.

**Как читать:**
- `tx packets`/`tx cells` **растут**, `tx rate` высокий, `errors 0` → multicast к абоненту идёт непрерывно. ✅ Со стороны DSLAM всё, идём к абоненту (модем/кабель/приставка).
- `tx rate ≈ 0`, пакеты не растут → multicast не доходит до порта: mvlan/агрегация/upstream (проверить `switch igmpsnoop mvlan show *`, `statistics vlan`, uplink).
- `rx packets` растут, `tx` нет → join идёт, ответного потока нет — upstream multicast.
- `errors` растут → проблема линии/PVC (тогда к профилю/линии).

## Сводная логика «не работает»

```
Нет картинки
   │
   ├─ statistics mac 8 → MAC приставки в IPTV VLAN есть?
   │        ├─ НЕТ → кабель/модем/приставка (L2 не доходит), к абоненту
   │        └─ ДА → Шаг 2
   │
   ├─ switch vlan portshow 8 → PVID = IPTV VLAN?
   │        ├─ НЕТ → сменить pvid на IPTV VLAN
   │        └─ ДА → Шаг 3
   │
   ├─ switch pktfilter show 8 → igmp=V, PPPoE-Only=D?
   │        ├─ НЕТ → switch pktfilter set 8 none
   │        └─ ДА → Шаг 4
   │
   ├─ statistics igmpsnoop port group 8 → группы есть?
   │        ├─ НЕТ → проверить mvlan (порт F?) → switch igmpsnoop mvlan show *
   │        │         └─ не F → switch igmpsnoop mvlan set <vid> 8:FU MULTICAST
   │        │         └─ F, а групп нет → приставка/модем (IGMP proxy, bridge) — к абоненту
   │        └─ ДА → Шаг 5
   │
   └─ statistics port 8 1 32 (дважды) → tx растёт, errors 0?
            ├─ ДА → DSLAM ок → модем/кабель/приставка — к абоненту
            └─ НЕТ → mvlan/агрегация/upstream multicast
```

**Короткое правило:** MAC → VLAN → V (pktfilter) → igmpsnoop group. Где первым «отвалилось» — там и причина. Если все четыре ок и трафик `tx` растёт — DSLAM чист, проблема у абонента (модем: bridge/VLAN/IGMP proxy; кабель; приставка).

## Про артефакты/зависания (для полноты, как вы сказали)

- **Артефакты/зависания** → сменить в профиле **задержку на `255 255`** (interleave), **PVC не пересоздавать**. То есть профиль с `interleave=255,255` — максимальная коррекция импульсных помех. Применить:
  ```
  adsl profile set <имя> interleave=255,255 <up> <down>
  adsl profile map 8 <имя> auto
  ```
  ⚠️ Порт «only IPTV» — согласовать. После смены проверить `statistics adsl show 8` (error second) и жалобы.
- **Просто не работает** → алгоритм выше (MAC → VLAN → V → igmpsnoop group), PVC не трогать.
